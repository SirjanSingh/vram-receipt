# 2026-11-15: Thanks, Jensen (the people's VRAM cluster)

## What changed and why

The first page read like a data essay. The goal became a shareable fan page: run a command, get a
tier and a "Thanks, Jensen" card, and optionally add your rig to a live global cluster.

- **Backend (Supabase, project `thanks-jensen`).** Table `rigs` with RLS on and no policies; the
  anon key can only call `submit_rig`, `get_rig`, `cluster_stats`, `leave_cluster`. Migrations in
  `supabase/migrations/`, all pushed. Later added `gpu_count` (1 to 16) and a generated
  `total_vram_gb`, because a DGX with 8 cards should count 256 GB, not 32.
- **Opt-in only.** The CLI shows the exact payload, then asks `[y/N]` (default no); piped runs and
  `--json` never send without `--join`. Country comes from the time zone, never the IP.
- **Core.** Tiers, cluster client, share card SVG, multi-GPU grouping on the receipt
  (`8x Tesla V100-SXM2 (32 GB each)`), and a name fix (`Tesla V100-SXM2-32GB` lost its dash).
- **Web.** Live cluster canvas, tier ladder, join flow, share card, rankings, revenue bar, a short
  "Dear Jensen, thank you" note, a 3D leather jacket (CC BY model, lazy-loaded three.js), a
  "Got a better idea?" contribute block, credits and developer links in the footer, and a
  "Laptop or other GPU" picker option (laptop cards have no launch MSRP, so they are not in the
  dataset).
- **Spam gate.** Joins now go only through the `join` edge function
  (`supabase/functions/join`). Web joins need a Cloudflare Turnstile token. CLI joins can't solve
  one, so the per-network limit in `submit_rig_gated` is the real control: at most 3 new rigs a day
  and 10 writes an hour per IP, with IPv6 counted per /64. It stores only a salted IP hash, deleted
  after 24 hours. The old anon `submit_rig` is dropped, and the whole-cluster flood guard is now a
  300 per 10 s backstop. The IP comes from `cf-connecting-ip`; a probe showed that forged
  `X-Forwarded-For` values are stripped. Secrets `IP_SALT` and `TURNSTILE_SECRET` are set on the
  function, never in the repo.
- **Security headers** in `web/public/_headers` (CSP, frame blocking, nosniff), plus the CLI id
  file set to owner-only (0600).
- **`--leave` fix.** The CLI parsed `--leave` but never acted on it; it now removes the entry.
- **Cluster scaling fix.** Chips were never removed, so a long-open tab grew without bound. Now
  slots are stable, chips that leave the latest-500 window fade out, and gaps compact inward.

## Verified

- 68 unit tests, `tsc --noEmit`, `npm run build`, `npm run build:web`.
- Browser (Chrome via Playwright) at 1280 and 375 px: no console errors, no horizontal scroll.
- Live DB: join and leave from the web page; anon cannot read the table; bad VRAM, junk names
  and 17 GPUs are rejected.
- CLI on the college DGX (RHEL 7.9, 8x V100): needed Node's glibc-217 build from
  unofficial-builds.nodejs.org, run from `/dev/shm`; the DGX is in the cluster as 8x V100.
